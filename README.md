# TrustRail + IntentLock

TrustRail is an independent portfolio project exploring a deterministic authorization layer between AI shopping agents and payment execution. IntentLock binds approval to a canonical purchase snapshot so a material change can require fresh human approval.

This is not affiliated with, endorsed by, or a representation of Stripe's internal systems. The initial project does not process real payments.

## Current status

**Milestone 1 — foundation.** The current implementation provides environment-backed configuration, a FastAPI application, database connectivity/readiness checks, a local SQLite default for tests, PostgreSQL configuration for containerized development, and a small integration test suite. Purchase and payment workflows are intentionally not implemented yet.

## Architecture (current milestone)

```text
HTTP client
    |
    v
FastAPI application
    |-- GET /       (redirect to interactive API docs)
    |-- GET /health  (process liveness)
    |-- GET /ready   (database connectivity)
    |
    v
SQLAlchemy Engine ---- SQLite for local tests / PostgreSQL in Compose
```

Later milestones will add domain services and persistent models without allowing the AI model to make authorization decisions.

## Requirements

- Python 3.12 or 3.13
- Git
- Optional: Docker Desktop with Docker Compose v2 for PostgreSQL/container workflows

## Windows PowerShell: local setup

From the directory where you want the repository:

```powershell
mkdir trustrail
cd trustrail
# Place the project files in this directory, or clone your repository here.
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m pytest
uvicorn app.main:app --reload
```

If PowerShell blocks activation, you can run the environment's Python directly instead:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

The app defaults to a local SQLite file when `DATABASE_URL` is not set. This is a convenience for early development and tests, not the intended multi-user deployment database. The `.env.example` file documents configuration but is not automatically loaded; to use PostgreSQL from PowerShell, set `$env:DATABASE_URL = "postgresql+psycopg://trustrail:trustrail_dev_only@localhost:5432/trustrail"` for that shell session.

## Docker Compose: PostgreSQL + API

Install and start Docker Desktop first. Then, from the repository root:

```powershell
docker compose up --build
```

Open `http://localhost:8000/` for the interactive API docs, or visit `/health` and `/ready` for service checks.

The credentials in `docker-compose.yml` are development-only. Do not reuse them in a shared or production environment. Database migrations and persistent domain tables arrive in subsequent milestones.

## API checks

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8000/ready
```

Expected liveness response:

```json
{"status":"ok"}
```

Expected readiness response when the database is reachable:

```json
{"status":"ready","dependencies":{"database":"ok"}}
```

When the database is unavailable, `/ready` returns HTTP `503` with a generic `database_unavailable` reason. It does not expose credentials or low-level driver errors.

## Tests

```powershell
python -m pytest
```

Tests currently cover liveness, database readiness using the configured local database, and unknown-route behavior. The test results should be generated by running the command in the environment you use; CI is configured for Python 3.12 and 3.13.

## Security posture and limitations

- No real payment provider or card data is used.
- There is no user authentication yet; all future protected routes must enforce it server-side.
- `/health` indicates process liveness only; `/ready` checks a database query.
- Local SQLite is not suitable for validating production concurrency guarantees.
- Compose credentials are intentionally simple local-development values.
- This milestone does not yet define authorization policies, approvals, idempotency, ledger entries, webhook signatures, or audit tamper evidence.
